# 03: 배포 연결

**What to build:** 짧은 주소가 실제 도메인에서 동작한다. `to2.at`은 Cloudflare에, 백엔드는 Railway에 올라가고 `api.to2.at`이 그것을 가리킨다. 기능이 아직 적을 때 배포 경로를 먼저 뚫어, 나중에만 드러나는 함정(커스텀 도메인, 운영 오리진, 크롤러 접근)을 미리 밟는다.

**Blocked by:** 02 (배포할 대상이 있어야 한다)

**Status:** ready-for-human

- [x] 백엔드가 **Dockerfile로** 빌드된다. 플랫폼 기본 빌더는 Gradle toolchain을 읽지 않아 잘못된 JDK로 빌드하므로 쓰지 않는다 (ADR: 스펙의 배포 결정)
- [x] PostgreSQL 서비스가 **명시적 메이저 버전 태그**로 고정된다. 떠 있는 기본 태그는 더 낮은 메이저로 해석된다
- [x] 플랫폼이 주입하는 데이터베이스 URL은 프레임워크가 파싱할 수 없는 형식이므로, 데이터소스 URL을 개별 연결 변수에서 조립한다
- [x] 헬스체크 경로가 붙고 애플리케이션이 플랫폼이 지정한 포트를 듣는다
- [ ] Worker가 배포되고 `to2.at` 커스텀 도메인에 연결된다
- [ ] `api.to2.at`이 백엔드를 가리킨다
- [x] 모노레포에서 각 배포 대상이 자기 루트 디렉터리와 watch path를 가진다. **프론트만 고쳤을 때 백엔드가 재배포되지 않는다** (재배포는 모든 Owner를 로그아웃시킨다)
- [ ] 운영에서 시드된 Code 하나를 열면 Interstitial을 거쳐 Target으로 이동한다

## 남은 일 (사람만 할 수 있음)

설정과 빌드는 끝났고 프로덕션 이미지가 JDK 25로 기동하는 것까지 확인했다. 남은 것은 계정 접근이 필요한 부분뿐이다.

- [ ] Railway 프로젝트에 연결하고 환경변수를 넣는다 (README의 표 참고)
- [ ] `to2.at` 커스텀 도메인을 Cloudflare Worker에 연결한다
- [ ] `api.to2.at`을 Railway 백엔드로 향하게 한다
- [ ] 카카오 콘솔에서 OIDC를 켜고 운영 redirect URI를 등록한다
- [ ] 운영에서 짧은 주소 하나를 열어 Interstitial을 거쳐 Target으로 가는지 확인한다
- [ ] 카카오톡에 붙여 Target의 미리보기 카드가 뜨는지 확인한다 (10번의 마지막 기준 — 크롤러는 공개 URL에만 접근하므로 여기서만 검증된다)

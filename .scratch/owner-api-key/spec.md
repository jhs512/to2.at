# Owner의 API 키로 Link를 관리한다

사용자의 구현 요청에 따라 카카오 로그인 세션을 매번 추출하는 대신 Owner가 자기 API 키를 발급하여 개인 스킬에 등록한다. 기존 카카오 로그인과 Operator 경로는 유지한다.

- 카카오 로그인한 Owner만 자기 키를 발급·목록 조회·폐기한다. 키 인증으로 새 키를 발급하거나 다른 Owner의 키를 관리할 수 없다.
- 여러 키를 허용한다. 표시 이름과 발급 시각, 폐기 시각을 제공하며 원문은 최초 발급 응답에서만 반환한다. 서버에는 256비트 무작위 키의 SHA-256 해시만 저장한다.
- Bearer 키는 /me, /links 및 /links/{Code}에만 사용하고 세션에 저장하지 않는다. 잘못된 키는 401이며 카카오 로그인으로 리다이렉트하지 않는다.
- 키로 인증한 Owner도 기존 Link 소유권, Target 검증, Code 유지 규칙을 따른다. 폐기 이후 새 요청은 거부한다.
- 대시보드에 키 발급·복사·폐기 UI와 원문 일회 표시 안내를 제공한다.
- 개인 CLI는 숨김 입력으로 키를 설정하고 개인 비밀 저장소 또는 비밀 환경변수에서 읽는다. 명령 인수와 로그에 원문을 넣지 않는다. 공개 호출에는 키를 보내지 않고 리다이렉트와 쓰기 재시도를 하지 않는다.

## 검증 seam

기존 Seam A: 실제 PostgreSQL 18과 MockMvc로 카카오 세션 발급, Bearer Link 생성·조회·삭제, 다른 Owner 거부, 잘못된 키·폐기된 키 거부 및 원문 저장·목록 노출 방지를 확인한다.
기존 Seam B: Worker 전체 테스트로 공개 경로 회귀를 확인한다.
CLI: loopback 모의 HTTP 서버로 Bearer 전송, 공개 무인증, 오류와 비밀 비노출을 확인한다.

## 운영 경계

격리 worktree의 구현·검증·커밋과 개인 스킬 업데이트다. 배포·운영 마이그레이션·운영 키 발급은 실행하지 않는다. 확인되지 않은 운영 회원 번호는 사용하지 않는다.

## 운영 승인 갱신
2026-10-13 사용자가 최종 검토 후 main 반영·푸시·운영 배포와 검증을 명시적으로 요청했다. 앞선 배포 금지는 해제됐다. 본인 로그인 없는 운영 키 발급이나 회원 가장은 하지 않는다.

# 외부 생성·복사는 Owner별 생성 요청 결과를 재사용한다

Java 비주얼라이저에서 긴 공유 Target을 넘겨 로그인 후 생성·복사한다. 로그인 왕복·새로고침·응답 유실·동시 탭이 같은 생성 요청을 반복하므로 UI에서 버튼을 잠그는 것만으로 중복 Link를 막을 수 없다.

일반 생성은 같은 Target을 여러 Link로 만드는 기존 계약을 유지한다. 외부 흐름은 Target에서 만든 결정적인 UUID를 선택적 requestId로 전달하고 Owner별로 저장한다. Owner 행 잠금 뒤 조회·생성하고 DB 고유 인덱스로 불변식을 보장한다. 전역 Target 중복 제거와 별도 로그인 복귀 URL을 추가하는 대안은 기존 Link 의미와 OAuth 경로를 바꾸므로 제외했다.

대가로 한 Owner의 외부 생성은 짧은 트랜잭션 동안 직렬화된다. 같은 공유 Target을 다시 열어도 기존 Code를 사용하며, 해당 Link를 삭제·Suspension하거나 Target을 바꿔도 자동으로 새 Code를 발급하지 않는다. 의도적으로 별도 Link를 만들려면 일반 생성 화면을 사용한다.

긴 Target은 to2.at 진입 주소의 fragment로 전달하고 JSON 본문으로 API에 보낸다. 쿼리 전달도 호환하지만 Cloudflare의 요청 URL 16KB 제한 때문에 긴 공유 URL에는 권장하지 않는다. 브라우저 로컬 저장소에는 Target과 요청 식별자만 저장하며 API 키와 로그인 자격 증명은 저장하지 않는다. 저장소가 없으면 자동 생성을 중단해 로그인/새로고침 시 Target 유실과 중복 생성 위험을 드러낸다.
